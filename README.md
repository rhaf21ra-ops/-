# قسطها: ملف واحد للنشر على Netlify

موقع Next.js 13 (عربي RTL) + قاعدة بيانات Supabase. يُبنى على Netlify بخطوة واحدة (`npm install && npm run build`).

## ما الذي يعمل (الوضع الحقيقي مع Supabase)

| الجزء | الحالة |
|---|---|
| التسجيل والدخول، التحقق من الهوية بالكاميرا ومراجعتها، الأدوار والصلاحيات المخصصة | حقيقي |
| المنتجات (مع رفع الصور لمخزن Supabase)، المخزون، التصنيفات | حقيقي. التاجر يضيف ويعدّل، ومنتجات التاجر غير المفعّل مخفية |
| السلة والدفع النقدي والتقسيط (`place_order`): الأسعار والمخزون والعمولة والقسط تُحسب في الخادم | حقيقي |
| ربط الموظف بشركته، أهلية وسقف الموظف من الشركة | حقيقي |
| قرار الشركة ثم قرار الإدارة، العقد وجدول الأقساط تلقائياً، تسجيل الدفعات، حالات الطلب والتوصيل، التسويات، الإشعارات | حقيقي (دوال خادم مختبرة) |
| فحص الاتصال | صفحة `/status` |
| ربط شركة توصيل ودفع إلكتروني وفواتير PDF | غير موجود (التوصيل يدوي) |

## الوضع التجريبي (بدون Supabase)

إذا لم تضف مفاتيح Supabase يعمل الموقع بوضع تجريبي كامل: التسجيل وتسجيل الدخول والتحقق من الهوية (بالكاميرا) والأدوار والصلاحيات المخصصة، وكل شيء محفوظ في متصفحك فقط (لا يُشارك بين الأجهزة وليس آمناً).
- رابط المنصة: `/`
- رابط الإدارة: `/admin-login` (أول من يفتحه ينشئ حساب المالك، وهو الوحيد)
- من `/admin/staff` ينشئ المالك الحسابات والأدوار المخصصة ويمنح الصلاحيات ويسحبها، ومن `/staff/identity` يراجع الموظف الهويات.
بمجرد إضافة المفاتيح أدناه يتحول الموقع تلقائياً إلى الوضع الحقيقي.

## الخطوات (مرة واحدة)

### 1) قاعدة البيانات (Supabase)
1. أنشئ مشروعاً جديداً في https://supabase.com
2. **Authentication > Providers > Email**: أوقف خيار **Confirm email** (لا يوجد بريد/واتساب للتأكيد، والتحقق يتم بمراجعة الهوية).
3. **SQL Editor**: الصق محتوى `supabase/setup_all.sql` كاملاً ونفّذه مرة واحدة. ينشئ الجداول والصلاحيات والمخازن الخاصة والفروع الـ156.
4. **Project Settings > API**: انسخ `Project URL` و`anon public` و`service_role`.

### 2) النشر على Netlify (يبني الموقع تلقائياً)
سحب المجلد إلى Netlify (Drag and drop) **لا يبني** Next.js، فلا تستخدمه. استخدم أحد الطريقين:
- **GitHub (الأسهل):** أنشئ مستودعاً خاصاً، ارفع محتوى هذا المجلد (المجلد نفسه وليس الـzip؛ الرفع من المتصفح يقبل 100 ملف في الدفعة، فارفع على دفعتين أو استخدم GitHub Desktop). ثم Netlify > Add new site > Import from Git. الإعدادات تُقرأ من `netlify.toml`.
- **Bolt:** افتح الملف في Bolt واضغط Publish (ينشر على Netlify).

ثم في Netlify > Site configuration > Environment variables أضف:

| الاسم | القيمة |
|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL |
| `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | المفتاح العام `sb_publishable_...` (أو استخدم `NEXT_PUBLIC_SUPABASE_ANON_KEY` بدلاً منه) |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role، اجعله Secret ولا تضعه في أي ملف |

وأعد النشر (Deploys > Trigger deploy). بدون المتغيرات يفتح الموقع لكن الدخول والتسجيل لا يعملان وتظهر رسالة بذلك.

### 3) تعيين المالك
1. سجّل حساباً من `/register` ببريدك. يمكنك التوقف عند خطوة الهوية.
2. افتح `supabase/create_owner.sql`، ضع بريدك، ونفّذه في SQL Editor. يصبح الحساب مدير المنصة (واحد فقط) ومفعّلاً.
3. لمنح موظف صلاحية مراجعة الهوية: يسجّل الموظف حسابه، ثم `supabase/make_staff.sql` ببريده.

## ملاحظات أمان
- مفتاح `service_role` يُستخدم فقط في `app/api/identity-file-url/route.ts` (خادم Netlify)، ولا يصل للمتصفح.
- التقاط الصور من الكاميرا قاعدة في الواجهة فقط. الخادم لا يستطيع إثبات مصدر الصورة، لذلك يقرر الموظف بعد رؤيتها.
- اضبط `typescript.ignoreBuildErrors` في `next.config.js` إلى `false` بعد تشغيل `npm run typecheck` وإصلاح أخطائه.
- `supabase/archive/` فيه ترحيلات قديمة متعارضة. لا تنفذها.

## ما لم يُختبر
- لم يُنفَّذ `npm install` ولا `npm run build` ولا `tsc` على هذا المشروع (npm محجوب في بيئة الإعداد). أول بناء يحدث على Netlify، وإن فشل فسجل البناء يعرض السبب.
- ملفات SQL اختُبرت على Postgres 16 محلي مع بديل بسيط لـ`auth` و`storage`، وليس على Supabase الحقيقي.
- مسار `/api/identity-file-url` والكاميرا وصفحة التسجيل الجديدة لم تُجرَّب في متصفح.


## طلب منتج غير مدرج
زر «طلب منتج غير مدرج» (في القائمة العلوية وأسفل المتجر ولوحة العميل والموظف) يفتح `/request-product`: يرسل العميل أو الموظف رابط منتج و/أو صورته من أي متجر محلي غير مسجل. تظهر الطلبات للإدارة في `/admin/requests` (صلاحية `requests.manage`، وهي ضمن دور «موظف الطلبات والتوصيل») لتتواصل مع المتجر، وتسجل السعر المؤكد، وتنقل الحالة (نتواصل مع المتجر، المتجر أكد، عرض جاهز، موافقة، تم الشراء، تعذر). يصل العميل إشعار عند كل تغيير ويتابع طلباته في `/requests`.
- قاعدة البيانات: `supabase/migrations/20261019000000_0017_product_requests.sql` (مضمّن في `setup_all.sql`). إن كانت قاعدتك منفذة سابقاً فنفّذ هذا الملف وحده في SQL Editor (آمن عند التكرار).
- الصور في مخزن خاص `request-images`، ولا يراها إلا صاحب الطلب والموظفون بالصلاحية.
- اختبار: `supabase/tests/product_requests_test.sql` (28 فحصاً على Postgres محلي).
- بدون Supabase يعمل بوضع تجريبي داخل المتصفح.

## الفواتير والعملات (الهجرة 0018)
**العملات:** الريال اليمني والريال السعودي والدولار.
- التاجر يختار عملة كل منتج عند رفعه ويكتب سعره بها.
- المشتري (عميل أو موظف) يختار من السلة أو صفحة الدفع العملة التي يدفع أو يتقسّط بها، فيُحوَّل السعر بسعر الصرف ويُقرَّب بالعملة المختارة (الريال اليمني بلا كسور، والسعودي والدولار بخانتين).
- أسعار الصرف يضبطها المالك فقط من `/admin/settings`، والقيم الأولية (140 للسعودي و530 للدولار) **تقديرية فعدّلها قبل الإطلاق**. يُحفظ سعر الصرف المستخدم مع كل بند طلب، فلا يتغير بعد الشراء.
- العقد والأقساط والمدفوعات والعمولات والتسويات كلها بعملة الطلب. سقف الموظف يُحسب بالريال اليمني (يُحوَّل مبلغ العقد عند الفحص). لوحات المجاميع تعرض بالريال اليمني بعد التحويل.

**الفواتير:** `/invoices`
- تصدر تلقائياً في قاعدة البيانات: فاتورة لكل تاجر عند الطلب النقدي، وعند موافقة الإدارة على عقد التقسيط (وفيها جدول الأقساط).
- العميل والموظف يريان فواتيرهما، والتاجر فواتير طلباته، والمالك والموظفون المصرّح لهم الكل. التعديل مستحيل من الواجهة.
- تنزيل PDF عربي لأي فاتورة، وفيها رمز QR يفتح `/verify/<الرمز>`: صفحة عامة تؤكد أن الفاتورة أصلية (الرقم والمبلغ والتاجر واسم العميل مخفياً جزئياً، بلا هاتف أو عنوان).
- كشف حساب التقسيط PDF: `/invoices/statement`.
- الـPDF يُبنى في المتصفح بمكتبتي `jspdf` و`html2canvas`، والـQR بمكتبة `qrcode` (أُضيفت إلى package.json).
- اختبارات القاعدة: `supabase/tests/currency_invoices_test.sql` (76 فحصاً).
- في الوضع التجريبي (بلا Supabase) تُصدر الفواتير داخل المتصفح عند إنشاء الطلب.
